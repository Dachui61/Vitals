# 3. 私有接口的使用与降级

- 状态：已接受
- 日期：2026-11-14
- 相关票据：03 / 23 / 25

## 上下文

本项目用到了若干**没有公开 API 替代**的系统接口：

| 用途 | 接口 | 公开等价物 |
|---|---|---|
| CPU 每核占用 | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` | 有（公开 Mach API） |
| 内存 | `host_statistics64(HOST_VM_INFO64)` | 有（公开 Mach API） |
| 内存压力 | `sysctl kern.memorystatus_vm_pressure_level` | 有（公开 sysctl） |
| Swap | `sysctl vm.swapusage` | 有（公开 sysctl） |
| 电源状态 | `AppleSmartBattery` 的 `BatteryInstalled`/`ExternalConnected` | 有（`IOPSCopyPowerSourcesInfo`，但本机返回空列表） |
| 热压力等级 | `ProcessInfo.thermalState` | 有（公开 Foundation） |
| **核型映射** | 设备树 `IODeviceTree:/cpus/cpuN@N` 的 `cluster-type` | **无**（`hw.perflevelN` 只给数量不给下标；`l2perflevels` 本机不存在；affinity 不支持） |
| **GPU 占用** | `AGXAccelerator` → `PerformanceStatistics` | **无**（公开 API 只给设备名） |
| **磁盘吞吐** | `IOBlockStorageDriver` → `Statistics` | **无**（公开 API 不给吞吐） |
| **CPU 温度** | `/usr/lib/libSMC.dylib` 私有符号 | **无**（见 ADR 1） |

另外用户还要求**背景透明度可调**（20%–100%），这决定了透明的实现方式。

## 决策

1. **允许在指标模块内使用私有接口**，但每一处都必须：写明为什么没有公开等价物、启动时做**能力探测**、探测失败时该指标降级为「不可用（原因）」而不是崩溃或显示 0。
2. **私有接口集中在各自的 provider 里**，`VitalsCore` 的模型层与 UI 层完全不知道数据来自公开还是私有接口。
3. **透明度只作用于背景与卡片**（面板底、卡片底、描边），文字/数值/曲线始终 100% 不透明。实现上：主题色统一乘一个透明度因子，文字色不参与相乘。
   - **不用 `NSWindow.alphaValue`**：那是整窗一起变（含文字），低透明度下文字不可读。
4. 探测失败必须**运行时可降级**：某个后端挂掉只影响那一个指标，其余照常显示。
5. 已知会周期性异常的读数要有专门处理：GPU 的 `PerformanceStatistics` 每 ~250 ms 会整组掉 0 → 连读 3 次取最大值，并按「近似值」标注。

## 后果

- 能拿到 macOS 不给公开 API 的关键指标（核型分组、GPU 占用、温度）。
- macOS 升级可能让这些接口失效：因此**能力探测与降级是必须实现的功能**，不是可选项；降级路径失效能直接被用户看到（显示"不可用"）。
- 私有接口意味着不能上架 App Store——本项目是自用工具，不受影响。
- 透明度做成"只变背景"意味着窗口背后的桌面会透出来，浅色主题下尤其明显；这是用户明确要的效果。

## 备选方案（被否掉的）

| 方案 | 否掉原因 |
|---|---|
| 只用公开 API | 核型分组、GPU 占用、CPU 温度全都没有，工具的核心价值被砍掉 |
| 整个窗口用 `NSWindow.alphaValue` | 文字随透明度一起变淡，低透明度下不可读 |
| 私有接口失败就让应用退出 | 一个指标挂掉不该拖垮整个工具 |
| 私有接口失败就显示 0 | 0 是合法读数（真的没在跑），用它冒充"读不到"会误导（GLOSSARY：不可用 ≠ 0） |
