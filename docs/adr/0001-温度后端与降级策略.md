# 1. 温度后端与降级策略

- 状态：已接受
- 日期：2026-11-14
- 相关票据：01 / 02 / 20 / 23 / 04

## 上下文

用户要的核心指标之一是 **CPU 核心温度（°C）**。问题是 macOS 27（Apple M6）没有给第三方应用任何公开的 CPU 温度 API：

- 经典 SMC 读键路径已死：`AppleSMCUserClient` 在 macOS 27 不存在；存活的 `AppleSMCKeysEndpoint` 用经典协议（132 字节 `SMCKeyData_t`）调用一律 `kIOReturnBadArgument`。
- `powermetrics` 在 macOS 27 **没有 smc sampler**（参数解析期即拒，exit 64；arm64e 二进制里 `smc`/`temperatur` 字节计数为 0）——所以"用特权跑 powermetrics 拿 °C"不是权限问题，是**根本没有这段代码**。
- IOReportHub 里没有 CPU die 温度通道（无特权枚举 8450 个通道 0 命中），且原始样本缓冲区在本机被 `KERN_NO_SPACE` 挡住，连 Apple 自己的 reader 也拉不到值。

而 `/usr/lib/libSMC.dylib`（macOS 27 给经典 SMC 路径配的继任者）**可以无特权读到数值温度**。

## 决策

1. **后端**：`dlopen("/usr/lib/libSMC.dylib")` + `SMCOpenConnectionWithDefaultService` / `SMCReadKeyAsNumeric` / `SMCGetKeyInfo`。键打包是**大端**（`'T'<<24|'C'<<16|'0'<<8|'P'`）。
2. **主键与降级链**：`Tp0j` → `Tp0g` → `Tp09` → `Tp07` → `Tp0b` → `Tp05` → `Tp0m` → `Tp0L`。
3. **禁用**：`Tg*`（GPU 侧）、`TVD0/TVDC/TVDP/TCMb`（SoC 封装热点，不是 CPU die）、`TH0x/TH0a/TH0b/TMVR/TR*d/TW0P/TT0P/TVN*/TN00`（环境/板级，CPU 负载下不动）。
4. **惰性探测**：平时直读主键；只在读不到 / 读值越界 / 读数长期不动时，才做一次探测（枚举 `T*` 候选 → 1–2 s 单线程 userInteractive 负载 → 取涨幅最大的键），结果落盘缓存（带机型与系统版本）。
5. **降级链**：libSMC → `ProcessInfo.thermalState` 四档 → 「不可用（原因）」。**任何一级都不得编造数字**，读不到就是不可用，不得显示 0，也不得用热压力等级反推温度。
6. **可信度标注**：键语义属"负载相关性推断"而非 Apple 确认，且**无法交叉验证**（powermetrics 只给压力等级；Apple 未公开 die 温度↔SMC 键对照表）→ 界面必须标**近似值**并显示传感器名（如「SMC Tp0j · 近似值」）。这是长期事实，不是权宜之计。
7. **热压力等级独立成行**，四档，**不叫"温度"**。

## 后果

- 温度可以在**无特权**下拿到 → 整个应用不需要任何特权组件，安装不需要管理员密码。
- 依赖一个私有 dylib：macOS 升级可能改符号或删键。因此必须有能力探测 + 自动降级，且**降级路径必须真的实现**（不能只写注释）。
- 数值可信度低于官方，必须靠标注诚实告知用户。
- 探测需要短暂占用一个核心，必须可取消且在界面上告知。

## 备选方案（被否掉的）

| 方案 | 否掉原因 |
|---|---|
| 特权 helper 跑 `powermetrics --samplers smc` | macOS 27 没有 smc sampler，root 也拿不到（票 02） |
| 特权 helper 说还原出的 168 字节 IOKit SMC 协议 | 协议虽已还原（票 20），但 root 是否放行从未验证，且 libSMC 已能免特权做到（票 01） |
| IOReportHub 私有协议 | 通道空间里没有温度通道；原始缓冲区被 KERN_NO_SPACE 挡（票 01） |
| 第三方工具（osx-cpu-temp / macmon / smc） | 走的是已死的经典 SMC 路径，且违反"不依赖第三方二进制" |
| 只显示热压力四档 | 用户明确要数值温度；且现在数值温度可得，放弃没有理由 |
| `NSWindow.alphaValue` 之类的整窗透明 | 与"文字始终可读"冲突（见 ADR 3 的取舍） |
