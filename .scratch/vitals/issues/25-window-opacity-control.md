# 悬浮窗的透明度调节

## Question

悬浮窗需要**可调透明度**。要定下：透明度作用在哪一层、怎么调、默认值、是否在交互时临时恢复，以及它与告警状态的关系。

候选问题：

1. **作用范围**：整窗一起变（含文字）/ 只变背景与卡片、文字保持不透明 / 只在未交互时变（鼠标悬停或正在操作时恢复 100%）。
2. **调节入口**：菜单栏菜单里的滑块 / 悬浮窗内的常驻控件 / 两者都有。
3. **默认值与范围**：默认 100% 还是更透明？可调区间多宽（30–100%？20–100%？）？
4. **与告警的关系**：温度告警时是否强制不透明（否则红色数字也看不清）？
5. **持久化**：跟随其它设置存 `UserDefaults`，启动后保持。
6. **实现手法**：`NSWindow.alphaValue`（整窗）还是逐层设置背景 alpha（文字不透明）——影响"文字在低透明度下还能不能读"。

产出：结论 + 对票 12（悬浮窗实现）与票 11（菜单栏）的增量要求；若结论影响观感，用原型验证（`prototypes/` 已有可运行的悬浮窗原型，加透明度控件即可）。

## Answer

**定稿：背景可调透明度（20%–100%，默认 100%），文字与曲线始终不透明；调节入口在菜单栏菜单的滑块；透明度一直生效，告警时不强制恢复不透明。**

具体约定：

- **作用范围**：只作用于**背景与卡片**（面板底色、卡片底色、描边），**文字、数值、曲线、图标始终 100% 不透明**。所以调到 20% 数字依然清晰可读，桌面能透过来——这正是要的效果。实现上：主题色统一乘一个 opacity 因子（`Theme.of(scheme, opacity:)`），文字色不参与相乘。
- **不用 `NSWindow.alphaValue`**：那是整窗一起变（含文字），低透明度下文字不可读，与本决定冲突。
- **范围与默认值**：**20%–100%，默认 100%**（第一次打开不透明，看得清）。存 `UserDefaults`，启动后保持。
- **入口**：**菜单栏图标 → 菜单里的滑块**（菜单里已有阈值设置与告警开关，透明度滑块放同一区域）。**悬浮窗内不放常驻控件**——尤其 L0 单行模式根本没有空间。
- **与告警的关系**：透明度**一直生效**，温度告警时不强制恢复不透明。理由：告警有系统通知 + 阈值带 + 数字变色三重提示，不依赖窗口不透明。
- **档位切换时透明度不变**（L0 一行字模式同样适用，底色一起变淡）。

原型已验证（`prototypes/VitalsPanelPrototype.swift` 第 3 版加了透明度滑块与 `VITALS_OPACITY` 环境变量；截图 `prototypes/vitals-opacity-levels.png`：100% / 60% / 30% 三档对照）。

**给票 12 的增量要求**：悬浮窗的每一层背景色（面板底、卡片底、描边）都要乘透明度因子；文字层不乘；L0 同样适用。
**给票 11 的增量要求**：菜单里加一个透明度滑块（20%–100%，步长 5%），与阈值设置放在一起，实时生效并写入 `UserDefaults`。
