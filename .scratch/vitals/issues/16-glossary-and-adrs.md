# GLOSSARY 与 ADR

## Question

把已达成的语言与决策固化下来：`GLOSSARY.md` + `docs/adr/`。

要交付：

- `GLOSSARY.md` 已在图表阶段建立初稿（根目录，见现有内容：核心温度 / 热压力等级 / 近似值 / 不可用 / CPU 占用 / 核型 / 采样间隔 / 滚动窗口 / 后端 / 降级链 / 特权组件）。本票负责**补全与校正**：随实现推进补上遗漏的术语、删掉没用上的、保持定义只有一两句且不含实现细节。特别要复核"不可用 vs 0"、"近似值 vs 精确值"这两组在界面上是否真的被区分对待。
- `docs/adr/` 至少三篇：
  1. **温度后端与降级策略**（依据 04 的结论；难逆 + 有真实取舍：公开 API 不可得 vs 私有 dylib 脆弱 vs 直接放弃数值温度）。要写明 macOS 27 上特权 powermetrics 已无 smc sampler（票 02）、IOReportHub 没有温度通道（票 01），所以选型只剩"私有 libSMC.dylib + 能力探测 + 降级到热压力四档"这一条现实路径。
  2. **为何不引入特权组件**（票 21 的决定）。这篇记取舍本身：私有 libSMC 已能免特权拿到数值温度，特权只剩功耗一个用途，不值得在用户机器上常驻一个 root 守护进程；顺带记录被否掉的选项（powermetrics 代跑、IOKit SMC 端点、第三方二进制）与各自原因。
  3. **私有 IOKit 接口的使用与降级**（票 03 引入的三处私有接口：设备树 `cluster-type` 读核型、`AGXAccelerator` 的 `PerformanceStatistics` 读 GPU 占用、`IOBlockStorageDriver` 的 `Statistics` 读磁盘速率）。每处都要写明：为什么没有公开等价物、能力探测怎么做、探测失败时指标如何降为"不可用"。这是"接受私有接口"这条决策的落地约束，与 ADR 2 的"不装特权组件"是一体两面。
- 每篇 ADR 按标准格式：上下文 / 决策 / 后果 / 备选方案（含被否掉的选项及原因）。
- 术语与代码一致：术语在代码里的命名也要对齐（如"不可用"在代码中统一用 unavailable 而非 nil/0）。

产出：`GLOSSARY.md`、`docs/adr/0001-*.md`、`docs/adr/0002-*.md`，以及一份代码术语对照的简短改动清单。

## Answer

**`GLOSSARY.md` 已补全，`docs/adr/` 三篇齐了**。

- `GLOSSARY.md`：原有术语保留；新增 **SoC 热点**（SoC 封装最热点，CPU+GPU 负载都会推高它，**不得当成 CPU 温度**）、**惰性探测**（只在已知传感器失效时才探测，结果与机型/系统版本一起落盘）、**窗口分档**（L0–L5，按尺寸决定显示哪些区块，太矮就退档而不是裁切）。复核了两组易混术语：「不可用」在代码里统一用 unavailable，**绝不与 0 混用**；「近似值」在界面上必须带「近似」二字 + 传感器名。
- `docs/adr/0001-温度后端与降级策略.md`：libSMC + `Tp0j` 降级链 + 惰性探测 + 三级降级 + 近似值标注；并列了 5 个被否掉的方案（特权 powermetrics、特权 168 字节协议、IOReportHub、第三方工具、只显示四档）。
- `docs/adr/0002-为何不引入特权组件.md`：温度免特权之后，特权只剩功耗瓦数，不值得常驻一个 root 守护进程；后果是安装免密码、攻击面缩小、代价是拿不到瓦数。
- `docs/adr/0003-私有接口的使用与降级.md`：逐项列出哪几个指标没有公开等价物（核型映射、GPU 占用、磁盘吞吐、CPU 温度），规定**每处私有接口都必须有能力探测 + 降级为「不可用」**，以及透明度的实现取舍（只变背景、不用 `NSWindow.alphaValue`）。
