# 要不要为"功耗"装一个特权组件

## Question

票 01 找到 `/usr/lib/libSMC.dylib` 后，**温度已经不需要特权了**——无特权就能读数值温度（Tp05/Tp09 实测随 CPU 负载上升）。所以特权组件剩下的唯一用途是**功耗（mW）**。问题因此变得很简单：

**为了一个"CPU 此刻耗多少瓦"的数字，值得在你自己的机器上常驻一个 root 守护进程吗？**

候选：

- (a) **不装任何特权组件**：v1 全部指标都走无特权后端；功耗这一格显示"不可用（需特权）"，或者干脆不占界面位置；功耗的用法写在文档里（"想看就自己跑一次 `sudo powermetrics --samplers cpu_power`"）。
- (b) **装可选的特权组件**：沿用已定的安全边界（LaunchDaemon + unix socket + 固定动作枚举 + 对端 uid 校验 + 审计日志），只提供功耗查询；不装也能用，菜单里给安装入口。
- (c) **一次性手动采样**：不做常驻组件，菜单里提供"以管理员身份运行一次并把结果贴回来"的一次性采样流程。

要一并定下：

- 功耗这一格在悬浮窗里的位置：并入"电源状态"卡片，还是干脆不在 v1 出现。
- 若做 (b)：组件的职责边界（只做功耗一个动作）、安装方式（.pkg 里可选勾选）、卸载是否干净。
- 若不做：GLOSSARY 里"特权组件"这个词是否还成立、ADR 第二篇写什么（"为何不装特权组件"而不是"特权组件的机制"）。

产出：结论 + 对票 14（特权组件）、票 15（.pkg 内容）、票 16（ADR 篇目）的直接影响。
