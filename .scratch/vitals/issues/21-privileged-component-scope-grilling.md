# 要不要为"功耗"装一个特权组件

## Question

票 02 定死了"特权拿不到温度"，但特权仍然能拿到 **CPU/GPU/ANE 功耗（mW）**（`powermetrics --samplers cpu_power --show-extra-power-info`）。要不要为这一个指标在你的机器上装一个常驻的 root 守护进程？

候选：

- (a) **不装任何特权组件**：v1 全部指标都走无特权后端；功耗留到"用户自己在终端跑一次 powermetrics 看"的文档里。
- (b) **装可选的功耗组件**：沿用已定的安全边界（LaunchDaemon + unix socket + 白名单 + 对端 uid 校验 + 审计日志），只提供功耗查询；不装也能用，菜单里给安装入口。
- (c) **一次性手动采样**：不做常驻组件，菜单里提供"以管理员身份运行一次 powermetrics 并把结果贴回来"的一次性采样流程。

要一并定下：

- 功耗是加进 v1 的悬浮窗，还是只作为 v2 的一项？（按已定口径，电源模块已包含"CPU 包功耗（若可得）"）
- 若做 (b)：组件的名字与职责边界（只读功耗 vs 未来可能扩展）、安装方式（.pkg 里可选勾选）、卸载是否干净。
- 若不做：GLOSSARY 里"特权组件"这个词是否还成立、ADR 第二篇写什么（"为何不装特权组件"而不是"特权组件的机制"）。

产出：结论 + 对票 14（特权组件）、票 15（.pkg 内容）、票 16（ADR 篇目）的直接影响。
