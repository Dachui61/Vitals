# 要不要为"功耗"装一个特权组件

## Question

票 02 定死了"特权 powermetrics 拿不到温度"，票 20 又把 `AppleSMCKeysEndpoint` 的协议完整还原了（取数被 `kIOReturnNotPrivileged` 挡住，授权在查键之前），所以**特权组件的用途取决于票 22 的实测结果**：

- 若 22 证实 root 可以读温度 → 特权组件的**主用途是数值温度**（辅以功耗 mW），值得装。
- 若 22 证实 root 也不放行 → 特权只剩功耗（mW）这一个用途，就要回答："为了一个瓦数，值得在你机器上常驻一个 root 守护进程吗？"

候选：

- (a) **不装任何特权组件**：v1 全部指标都走无特权后端；数值温度降级为热压力四档并写明原因；功耗留到"用户自己在终端跑一次 powermetrics 看"的文档里。
- (b) **装可选的特权组件**：沿用已定的安全边界（LaunchDaemon + unix socket + 键名白名单 + 对端 uid 校验 + 审计日志），提供温度（走还原出的 168 字节 SMC 协议）与功耗；不装也能用，菜单里给安装入口。
- (c) **一次性手动采样**：不做常驻组件，菜单里提供"以管理员身份运行一次并把结果贴回来"的一次性采样流程。

要一并定下：

- 特权组件是装进 v1 还是 v1.1（若 22 证实可用，v1 才有"真实数值温度"这个卖点）。
- 若做 (b)：组件的职责边界（温度 + 功耗两个固定动作，不接受客户端传入任意参数）、安装方式（.pkg 里可选勾选）、卸载是否干净。
- 若不做：GLOSSARY 里"特权组件"这个词是否还成立、ADR 第二篇写什么（"为何不装特权组件"而不是"特权组件的机制"）。

产出：结论 + 对票 14（特权组件）、票 15（.pkg 内容）、票 16（ADR 篇目）的直接影响。
