# 悬浮窗视觉与布局原型

## Question

浮窗长什么样？做一个粗糙但**可运行、可点击**的原型（SwiftUI + 假数据驱动，不需要接真实采集器），用于确定：

- 布局骨架：顶部状态条（CPU% / 温度 / 内存% / 电源状态）+ 每核曲线区（按 超频 2 / 性能 4 / 能效 6 三组着色）+ 告警色带与阈值刻度。
- 状态变体至少覆盖四种：正常、温度告警（黄/红）、温度不可用、helper 未安装（含"安装温度组件"的引导入口）。
- 窗口行为：默认尺寸、是否可缩放、隐藏标题栏、拖拽把手、置顶层级、多显示器上出现的位置。
- 中文文案与数字格式：温度整数还是一位小数、CPU 百分比是否取整、单位写法（°C / %）、"不可用"时的占位文案。

产出：原型源码作为本票的资产链接（放在 `research/` 或 `prototypes/` 目录下），并附一份简短的设计说明（各区域的作用与配色语义）。原型只求结构与手感，不求美观。

## Answer

**原型已建成并在本机跑通**，评审后视觉规范定稿如下。资产：[prototypes/VitalsPanelPrototype.swift](../../../prototypes/VitalsPanelPrototype.swift)、[prototypes/build.sh](../../../prototypes/build.sh)、[prototypes/vitals-prototype.png](../../../prototypes/vitals-prototype.png)（实际渲染截图）。

**布局骨架（自上而下）**：

1. 标题栏：拖拽把手（三点） + 「Vitals」+ 采样状态（绿点 + "1 秒刷新"）+ 关闭按钮
2. 四个指标瓦片一行：**CPU / 核心温度 / 内存 / 电源**
3. 温度卡：**核心温度**大数字（左）+ **SoC 热点**（右，次级字号）+ 底部一行**热压力等级**（标注"四档 · 不是度数"）
4. 每核占用：12 条并排迷你曲线，按核型着色，下方各标当前百分比
5. v2 三卡：**GPU 占用**（带进度条，标"近似值"）/ **磁盘**（读 / 写 MB/s）/ **网络**（↓ / ↑ KB/s）
6. 进程 Top 5：进程名 + CPU% + 内存，标题右侧标注"仅当前用户 · 只读"
7. 温度阈值色带：0–100 °C，蓝(0–70) / 黄(70–80) / 红(80–100)，当前值白色指针，刻度 "0 °C / 70 / 80 °C 告警 / 100 °C"
8. （**仅原型**：底部的状态变体与外观切换器，正式版去掉）

**定稿的视觉决策**：

- **每核曲线**：12 条并排迷你曲线（不合并成组），核型着色固定为 **超频核=橙红 / 性能核=蓝 / 能效核=绿**，每核下方显示当前整数百分比；副标题"60 秒滚动窗口 · 颜色区分核型"。
- **数字格式**：详情区温度 **一位小数**（57.6 °C），顶部瓦片 **整数**（58°）；CPU/内存整数百分比；磁盘一位小数，网络整数 KB/s。
- **主题**：**跟随系统浅/深**（用 SwiftUI `colorScheme` 派生一套语义色），浅色下卡片白底、描边与文字透明度相应调整。原型额外提供 跟随系统/浅色/深色 切换用于比对。
- **窗口**：**可缩放、内容自适应**；默认 470×860，最小 400×620；无边框、置顶（`.floating`）、可拖拽、无标题栏；拖拽把手固定在左上角。
- **告警表现**：**数字变色 + 阈值带**（不改变整个窗口配色）。≥70 °C 数字转黄，≥80 °C 转红，阈值带上同步变色。
- **状态变体**（正式版必须覆盖）：正常 / 温度告警（数字变黄红）/ 温度不可用 / 传感器识别中（进度条 +「正在识别温度传感器…」）。
- **不可用文案**：主文案「不可用」，副文案「macOS 未向无特权应用开放温度传感器」——**不显示 0，不隐藏原因**。
- **SoC 热点**与核心温度并排同卡，**字号更小**（次级信息），但保留传感器名与"近似值"标注。

**给票 12 的约束**：以上即为实现规格；原型代码可作为 `VitalsUI` 的起点，但要去掉原型控制栏、把假数据换成 provider 注入、曲线改用真实历史缓冲。
